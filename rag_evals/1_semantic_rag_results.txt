ANSWER
--------------------------------------------------------------------------------
Based on the codebase, privilege escalation is prevented primarily through a **Role-Based Access Control (RBAC)** policy implemented in **`permissions.py`** via the `PermissionPolicy` class. 

Here are the key mechanisms that enforce permissions and protect against unauthorized privilege escalation:

1. **Role Definitions (`Role` Enum)**
   Users are categorized into distinct privilege tiers (`admin`, `member`, and `viewer`):
   ```python
   class Role(Enum):
       ADMIN = "admin"
       MEMBER = "member"
       VIEWER = "viewer"
   ```

2. **Explicit Action-to-Role Mapping (`ROLE_PERMISSIONS`)**
   Actions are strictly gated behind permission strings (e.g., `"user:manage"`, `"task:delete"`, `"billing:view"`). High-privilege actions like managing users or assigning tasks are restricted strictly to the `ADMIN` role:
   ```python
   ROLE_PERMISSIONS: dict[str, set[str]] = {
       Role.ADMIN.value: {
           "task:create", "task:complete", "task:delete", "task:view",
           "task:assign", "report:view", "user:manage", "billing:view",
       },
       Role.MEMBER.value: {
           "task:create", "task:complete", "task:delete", "task:view",
           "report:view",
       },
       Role.VIEWER.value: {
           "task:view",
       },
   }
   ```

3. **Default Least-Privilege Fallback (`get_role`)**
   If a user's role is not explicitly found in the role store (`_user_roles`), `PermissionPolicy.get_role()` defaults them to the lowest privilege level (`Role.MEMBER.value`), preventing unassigned users from inheriting elevated privileges:
   ```python
   def get_role(self, user: User) -> str:
       return _user_roles.get(user.id, Role.MEMBER.value)
   ```

4. **Enforcement via `require()` and `can()`**
   Services enforce these permissions prior to executing sensitive code paths. Calling `policy.require(user, action)` checks whether the user's role is authorized for the action, raising a `PermissionError` if unauthorized:
   ```python
   def require(self, user: User, action: str) -> None:
       """Raise PermissionError if user's role does not allow action."""
       role = self.get_role(user)
       allowed = ROLE_PERMISSIONS.get(role, set())
       if action not in allowed:
           raise PermissionError(
               f"User '{user.username}' with role '{role}' cannot perform '{action}'"
           )
   ```

ANSWER
--------------------------------------------------------------------------------
Based on the codebase, the following methods check `is_active` before proceeding:

1. **`AuthService.get_current_user`** (in `auth.py`):
   Resolves a session token to a user and checks that `user.is_active` is true before returning the user (otherwise raising an `AuthError("User account is inactive")`).
   ```python
   user = self.db.get_user(user_id)
   if not user or not user.is_active:
       raise AuthError("User account is inactive")
   ```

2. **`TaskScheduler.tick`** (in `scheduler.py`):
   Iterates through scheduled tasks to materialize due schedules, and skips any schedule or whose owner is inactive:
   - It checks `if not schedule.is_active or schedule.next_run > now:` to skip inactive schedules.
   - It checks `if owner is None or not owner.is_active:` to skip materializing tasks for inactive schedule owners.

When `complete_task` is called with an expired (or invalid) session token, the call chain and failure mechanism proceed as follows:

### **Full Call Chain**

1. **Entry Point / Caller**
   * The caller (such as a CLI script or API endpoint in `main.py`) invokes:
     ```python
     task_service.complete_task(token, task_id)
     ```

2. **Task Service Layer (`task_service.py`)**
   * Inside `TaskService.complete_task(self, token: str, task_id: int)`:
     ```python
     user = self.auth.get_current_user(token)
     ```
     It immediately delegates the validation of the session token to the `AuthService`.

3. **Authentication Layer (`auth.py`)**
   * Inside `AuthService.get_current_user(self, token: str)`:
     ```python
     user_id = self._sessions.get(token)
     if user_id is None:
         raise AuthError("Invalid or expired session token")
     ```

---

### **Where and How It Fails**

* **Where it fails:** Inside **`AuthService.get_current_user()`** in **`auth.py`**, specifically at the lookup against the in-memory session dictionary (`self._sessions.get(token)`).
* **How it fails:** 
  1. Since the session token is expired (or missing/invalid), `self._sessions.get(token)` returns `None` because the token is no longer present in the `_sessions` dictionary (or was never there).
  2. The conditional check `if user_id is None:` evaluates to `True`.
  3. An **`AuthError`** exception is explicitly raised with the message `"Invalid or expired session token"`.
  4. Because this exception occurs before any database lookups, policy checks, or task updates happen, **execution halts immediately**, aborting the task completion workflow and bubbling the `AuthError` up to the caller.
